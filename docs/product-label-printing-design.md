# 商品ラベルPDF印刷機能 設計メモ

## 目的

完成済みの商品ラベルPDFをアプリに同梱し、商品ごとに選択してA4タテでプレビュー・印刷できるようにする。
現場ユーザーはPDFを編集せず、「商品を選ぶ」「印刷する」だけで使える状態を目指す。

## 運用方針

- アプリ本体はGitHub Pagesで配布できる静的Webアプリとして保つ。
- 商品ラベルPDFは `public/product-labels/` に同梱する。
- PDF追加・差し替え・削除は、当面はリポジトリ側で管理する。
- 画面から任意PDFをアップロードしてサーバーへ保存する機能は、GitHub Pagesでは扱わない。
- 将来必要になった場合だけ、端末ごとのローカルPDF登録機能を追加する。

## 画面構成

既存の「消費期限シール作成」画面に、印刷モードを切り替えるUIを追加する。

- 消費期限シール
  - 現在のA4横20面PDF作成機能。
- 商品ラベル印刷
  - 商品を選択する。
  - 登録済みPDFがある場合はA4タテPDFをプレビューする。
  - 印刷ボタンでブラウザの印刷ダイアログを開く。
  - PDFが未登録の商品は、未登録であることを表示する。

## データ設計

`src/productLabelPdfs.ts` を追加し、商品IDとPDFパスを対応づける。

例:

```ts
export const PRODUCT_LABEL_PDFS = {
  plain: '/product-labels/plain.pdf',
  'apple-cinnamon': '/product-labels/apple-cinnamon.pdf',
};
```

商品IDは既存の `ProductTemplate.id` を使い、商品マスタとPDFマスタを分離する。

## PDF配置

PDFは `public/product-labels/` に置く。
Vite/GitHub Pagesでは `public` 配下がそのまま公開されるため、アプリから相対URLで参照できる。

## 印刷仕様

- 商品ラベルPDFはA4タテ前提。
- アプリ側でPDFを再生成・再配置しない。
- iframeでプレビューし、印刷ボタンでiframeの `print()` を呼び出す。
- ブラウザ印刷時は倍率100%、用紙に合わせない設定を利用者に案内する。

## エラー表示

- 選択商品にPDFがない場合は「この商品の商品ラベルPDFは未登録です。」と表示する。
- PDF読み込みに失敗した場合は、再読み込みまたはPDF登録確認を促す。

## テスト方針

- 商品IDからPDFパスを取得できること。
- 未登録商品の場合は未登録として扱うこと。
- モード切替で既存の消費期限シール作成機能を壊さないこと。
- ビルド後も `public/product-labels/` のPDFが参照可能なパスになること。

## スコープ外

- 画面からPDFをアップロードしてGitHub Pages側へ保存する機能。
- PDFファイルの編集。
- 商品ラベルPDFの自動生成。
- 認証付き管理画面。
